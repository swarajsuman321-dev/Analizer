## 2. Product purpose and user decisions

The user's priorities are, in order: **plot data, understand it easily, compare
chosen signals/data, and account for every source field**. Extra engineering
controls must not make ordinary plotting difficult.

Keep these decisions when refining the application:

- One shared cyan A (`#00D2FF`) / orange B (`#FF9F1C`) pair across compatible time
  graphs, with one combined value table. Shorter signals show Unknown outside
  their support; they do not pull the cursors onto their own endpoints.
- Add blank graphs on demand; let users choose channels, move, resize and remove
  graphs. Preserve source data, channel assignments and saved layouts.
- Inspect all selected traces at one mouse time, with markers/readings for each.
  Readouts must not cover the graph or make its canvas bounce.
- Display time in minutes while retaining original timestamps and precision.
  Sample/frequency coordinates must retain their own domains.
- Give Analysis and Comparison clear jobs. Comparison must support three or more
  signals and keep its reference/candidate identities explicit.
- Actuator analysis uses the applicable ON/OFF interpretation: zero OFF, finite
  nonzero integer ON. This is not a rule for every numeric sensor or enum code.
  Overlap, missing data, acquisition gaps and censored boundaries need explicit
  support policies. Command state does not prove physical flow or actuation.
- Hide exported cursor guides by default; retain cursor times, values and interval
  statistics. Annotation opt-in must not change live cursor state.
- Keep secondary panels/tools folded or reachable on demand. The user authorized
  hiding unnecessary default controls during the workflow recovery; unrelated
  feature removal still needs confirmation.
- Ask about material ambiguities. Keep limits, phase dictionaries, calibration
  curves and acceptance criteria configurable; invent none. Four report sections
  may continue onto readable extra pages.
- Installed Setup, standalone EXE and complete portable ZIP must share features,
  versions and verified edition-appropriate update/recovery support.

The current release uses **confirmed program-start alignment**, one origin per
recording, and blocks absent program-start evidence. Preserve that current
behavior when integrating older elapsed-time comparison work. Do not silently
reinstate an earlier recording-start fallback.

## 8. Reproduction and handover hygiene

Use Python 3.12 and the repository's pinned build dependencies. Read
[BUILD_EXE.md](../BUILD_EXE.md), the [distribution policy](DUAL_DISTRIBUTION_POLICY.md)
and the [installer guide](WINDOWS_INSTALLER.md) for platform and packaging steps.

Typical source validation, from the chosen checkout:

```sh
QT_QPA_PLATFORM=offscreen python -m unittest discover -s tests -v
QT_QPA_PLATFORM=offscreen python tools/check_release_acceptance.py --output /tmp/analizer-acceptance
```

Use isolated `ANALIZER_SETTINGS_DIR`, `ANALIZER_OUTPUT_DIR`, `MPLCONFIGDIR` and
`XDG_CACHE_HOME` directories so tests cannot alter personal configuration. Windows
EXEs must be built and exercised on native Windows; Linux offscreen results do
not replace those gates.

Private uploads, original/extracted private traces, generated measurement reports,
credentials, virtual environments and caches are excluded from this handover.
The portable evidence summary retains counts/statuses and log hashes; raw
environment logs and private report bundles remain local. Existing recordings
already approved and committed to the repository retain their prior status.
