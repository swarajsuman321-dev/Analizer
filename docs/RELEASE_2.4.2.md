## Graph and data workflows

- **Change Trace Color…** is directly available from Channel, Properties, Data Portal channel context and the chart's per-trace context menu. The picker changes trace appearance while preserving numerical ranges, cursor/sample locks, history and identities. Legend/axis/readout colors follow the trace where applicable. Cancel leaves colors and the view unchanged. No graph-background feature is added; existing theme controls remain.
- **Compare Data…** in the main toolbar selects channels from any loaded recordings, partitioned by file with per-file checkboxes, units/search and selection counts. **Open More Files…** uses the normal importer/TDMS review and returns to the chooser without automatically plotting the new import. **Add to Comparison** adds new stable channel IDs, retains existing Comparison work and avoids duplicating already-present IDs. Context shortcuts add selected channels or one file. This is ordinary plotting, not an invented engineering evaluation: native clocks/units remain, incompatible coordinate domains stay in separate panes, and no scores/alignment/calibration are guessed. Existing configured engineering comparison remains available.
- **Fullscreen Selected Graph** (F11) is available in View and the graph header; the chart's **Full Screen Graph** action targets the clicked pane. Only that pane expands, with shared zoom/pan/cursor controls, Mouse X/Y, A/B cards and channel values/statistics. Initial readout sizing follows the visible table contents; its divider remains adjustable to share space with the graph. F11, Esc or **Exit Fullscreen** restores its workspace position and window arrangement while retaining deliberate graph navigation. Original pane identity, data, locks and unit axes are preserved. Existing time-lock behavior remains active when enabled.
- The compact **Panels** button expands/folds supporting docks. Fresh workspaces fold exactly **Properties**, **Channel Math**, **Channel Table** and **Interval Measurements** by default, while Engineering Controls, Readout and Data Portal remain available. Engineering Controls remains the default tab in its existing group. Explicit saved layouts, including legacy Qt layouts without folding metadata, take precedence. This latest approved default supersedes earlier all-panels-open guidance. Existing View routes, Show all panels and explicit Focus Graph remain available.
- The current manual uses the visible **Plot Appearance / Layout**, **Engineering Diagnostics**, **Signal Processing / Derived Channels**, **Import / Export Utilities**, **Export Utilities** and **Presets / Extensions** menu names. More and Tools expose the same actions; main About manual/version/update access remains intact.
- The selected-channel interval detail card in **Readout** scrolls longer statistics while keeping the dock compact. The complete details remain accessible without forcing a taller dock.

## Remembered dialog folders

The twenty existing open/save dialog call sites now use shared persistent folder history. Each purpose keeps its own last folder across app restarts and runtime replacement: recordings, workspace restore/save, appliance profiles, channel presets, reports and alternative exports, engineering source/reference files, simulation images, extensions and offline update manifests. The first save for each purpose still starts in the configured output root or its normal subfolder; a deliberate destination choice becomes that purpose's remembered override. Suggested filenames, file filters and ordinary Qt return values remain intact. Cancelling does not change history, and removed folders fall back to their nearest existing parent.

The bounded, versioned **dialog-history.json** lives in the per-user settings directory, normally **%APPDATA%/ApplianceSignalStudio**, outside replaceable runtimes. It stores folder paths, not selected filenames, measurement contents or an activity log. A configured settings-directory override continues to apply. Recent-file menus and activity-log workflows are not part of this verified implementation; their requested behavior remains subject to clarification.

## Quiet installed-app updates

The current installed-app update launcher passes **`/VERYSILENT`** instead of **`/SILENT`** to Inno Setup. `/SILENT` skips the wizard but still displays installation progress; `/VERYSILENT` suppresses that progress window as well. Existing message suppression, installation directory, no-restart and logging arguments remain. This applies to Setup launched by the installed-app updater, not a Setup EXE deliberately opened by a user.

Manual first installation, repair and manual upgrades keep their normal interactive wizard. The change does not disable Windows security/publisher prompts or organizational restrictions. Standalone EXE replacement and complete ZIP/folder updates retain their existing mechanisms; all delivery forms keep matching versions and edition-specific feeds.

Staged-runtime health verification still precedes installation. Setup logging, process/exit-code checks, new-startup version/path and restored-workspace acknowledgement, independent recovery snapshots and previous-runtime retention remain required. Hiding progress must not turn a failed installation into a reported success. Installed late-startup fallback can restart the previous runtime while full registration/shortcut restoration still requires rerunning its previous official Setup.

## Important one-time transition

**An installed v2.4.1-or-earlier copy may show Setup progress once while installing v2.4.2.** The application already running owns the updater: its embedded launcher still passes `/SILENT`. The downloaded v2.4.2 payload cannot retroactively change that old launcher. Once v2.4.2 is installed and running, subsequent installed-app updates use `/VERYSILENT` and no longer show Setup's progress window under normal conditions.

Running the downloaded Setup manually remains an interactive installation, including when used to install this fix. Do not interpret a one-time old-updater progress window or a deliberately opened manual wizard as failure of the new updater.

## Remaining limits

The update harness invokes the current production updater against actual pinned v2.4.1 GUIs; it does **not** click that immutable older binary's update interface. Visibility is sampled every 25 ms and does not certify every shorter transient flash or Windows security prompt. Fallback uses ordinary **--restore**; retained previous-version GUI survival and the independent recovery snapshot's load are checked separately. Restarting a retained installed runtime does not fully roll back registration/shortcuts; rerunning its previous official Setup can still be required.

The Windows CI account is privileged; per-user registration scope is verified, but this is not a separate standard-user login or a clean VM without Python, and it does not certify antivirus behavior. The release is unsigned because no publisher identity was supplied. Physical mouse/wheel/box/keyboard checks, Windows 100/125/150/200% scaling, multi-monitor/GPU behavior, keyboard-only/screen-reader use, prolonged sessions and actual corporate-network policies remain separate human/platform checks. Source/offscreen geometry and native automated outcomes retain those limits.

Engineering calibrations, phase meanings and acceptance limits remain configurable; no new manufacturer values are introduced. Source measurements, settings, templates, workspaces and outputs remain outside runtime replacement/uninstall ownership.
